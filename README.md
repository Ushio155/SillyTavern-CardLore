# SillyTavern-CardLore 插件

「填写即生成」角色卡 + 世界书生成器（SillyTavern 1.18.0 实测，兼容移动端窄屏）。

## 许可与开发声明

- 本插件以 **MIT 许可证** 开源（见 `LICENSE`），可自由使用、修改与再分发（保留版权声明即可）。
- 本插件功能需求设计由作者本人完成，借助 **DeepSeek Harness**（AI 编程助手）辅助完成代码实现、调试以及发布相关样板工作，详细声明见 [`AI-DISCLOSURE.md`](./AI-DISCLOSURE.md)。
- 使用本插件请同时遵守 SillyTavern 自身的许可与使用条款。

## 安装

**方式 A：从 GitHub 一键安装（推荐）**
ST 顶栏 → 扩展程序（魔法棒）→ 管理扩展程序 → **Install extension** → 粘贴仓库地址：

```
https://github.com/Ushio155/SillyTavern-CardLore
```

**方式 B：手动放置**
把整个 `SillyTavern-CardLore` 目录放进 `public/scripts/extensions/third-party/`。

安装后**刷新浏览器页面**（扩展在客户端发现/加载，需刷新才生效）。

> ⚠️ **只保留一份**：用面板安装（方式 A）会装到 `data/<用户>/extensions/`，而 ST 的静态目录 `public/` 优先级更高——若 `public/scripts/extensions/third-party/SillyTavern-CardLore` 下还留着旧的手动副本，面板装的版本会被它**完全遮蔽**（页面看似装好了，跑的却是旧代码）。请在面板与手动目录之间二选一，另一个删掉。更新时用面板的「更新」/「切换分支」，重复点「Install extension」只会得到 `Directory already exists` 报错。

## 使用

**入口（三处）**：
1. 角色列表工具栏，「新建角色」按钮**左侧**的琥珀色 ✨ 按钮（悬停显示"一键生成"）—— 最显眼，推荐
2. 顶栏左侧「扩展程序」魔法棒菜单内的 ✨ 图标
3. 「扩展程序」设置面板中 CardLore 标题栏内的「✨ 一键生成」按钮（无论折叠/展开都可见，点击直接打开生成器）

点击后打开生成器：

1. 粘贴**任意原始文本**（无需关心插件格式）。输入框右上角「**展开**」可切换全屏编辑，方便查看和修改整段文本（编辑实时同步，`Esc` 或「完成」收起；全屏内也可直接「解析预览」）。
   - 也可以用本地文件作为素材：提示行「载入示例」右侧的琥珀色「**导入素材**」支持拖入或点击选择 **.txt / .md / .docx**（可多选、可重复添加），添加后文件名以标签显示在输入框下方（点 × 移除）。适合导入 Word/纯文本里的设定稿、小说、大纲等长文，再交给「AI 适配」整理。
2. 点「**AI 适配**」（🤖，解析预览左侧）——通过 **OpenAI 兼容接口**自动整理成插件格式并立即预览。已添加的素材文件会与输入框文本**一并合并**送入；整理完成回填后素材列表自动清空，避免重复合并。
   - **默认方案（推荐，免填 Key）**：预设方案列表第一项。直接借用 ST 顶部「**API 连接**」里的来源、模型与额度——插件内不用填接口地址和 API Key，ST 里能正常聊天就能用。切换方式：「预设方案」点第一项「**启用**」，或在「AI 接口设置 → 调用方式」里点「使用 ST 当前连接」。
   - 想用别的 Key/额度：展开「AI 接口设置」→ 展开「**预设方案**」选一家（DeepSeek / OpenAI / Kimi / 通义 / GLM / 硅基流动 / Groq / OpenRouter / 本地 Ollama），点「填入」自动填好地址与模型（默认填入各家当前最具性价比的模型，如 DeepSeek 为 `deepseek-v4-flash`）；填 API Key 后点「保存设置」。
   - 「调用方式」也可直接手动切到「自定义接口」，自行填 OpenAI 兼容地址 / API Key / 模型（不填 Key 时地址会按 ST 当前来源预填）。
   - 提示词可自行修改；点「重置默认提示词」一键恢复，避免改崩。
   - **提示词分层（防"待适配文本被当成指令执行"）**：素材一律作为「数据」放进 user 层的区块标记内（`<<<CARD_LORE_MATERIAL_BEGIN>>> … <<<CARD_LORE_MATERIAL_END>>>`），转换规则与字段格式只放 system 层，区块之后再补一段「尾部确认」；素材里出现的"你是…""你的唯一任务是…""禁止…"等命令句会被原样搬进输出字段（通常是「系统提示」），不会被当作指令执行。素材本身就是一段提示词时（例如"角色卡设计师"人设），转换结果应当是**这段提示词对应的角色卡**，而不是按它去生成新内容。
   - **输出守卫 + 自动重试**：每次「AI 适配」都会校验输出是否落在固定字段结构内（`名称:`/`描述:`/`系统提示:`/【世界书】…），并计算**素材信息保留率**；不合格（把素材当指令执行、照素材自带模板作答、结构合法但内容几乎全是新编的"幻觉卡"、空输出）会自动追加修正层重试（最多 3 次，取"字段命中 → 素材保留率"最优的一份）；输出末尾疑似被 max_tokens 截断时会自动追加一次「续写」并拼接。状态栏会注明本次是否触发兜底："（首次输出跑偏，已自动修正重试）/（检测到截断，已自动续写）"，没有任何注明即为一次成功。
    - **名称归属守卫**：素材标题若本身是**作品名/主题名**（如 `# 【角色卡名称】《某某淫行录》`），「名称」应当就是这个作品名；模型若把素材里被"你"指代的**用户角色**（也就是你自己的人物）写成「名称」或整段「描述」，会按素材卡名自动校正并在状态栏注明"（「名称」已按素材卡名校正为「…」）"；素材里只在正文提过一次《书名》这类弱信号不硬改，只提示"请核对"。
3. 「解析预览」→ 查看角色卡字段 / 世界书条目 / 校验报告（AI 整理后会自动执行）。
   - **解析保真**：字段值一直累积到下一个字段行为止，**字段内的空行与 Markdown 标题（`## 核心规则`、`## 角色备注`）都算内容**，不会在第一个空行处被截断；`替代开场白: - 节点二` 这类「首条写在字段名同一行」的列表也不会丢第一条。
   - **落位自检**：若确有输入行没能写进角色卡（字段名不是标准写法、或文字出现在第一个字段之前），校验报告会给出「无法归属的文本」/「有 N 行内容没有写入角色卡」告警，而不是静默少内容。
4. 「清空预览」→ 清除当前解析结果（输入框文本保留，便于修改后重新解析）。
5. 「应用」→ 自动：
   - 保存独立世界书（`saveWorldInfo`，重名自动加序号）
   - 导入角色卡（`POST /api/characters/import`，`file_type=json`）
   - 卡片 `extensions.world` 绑定世界书
6. 或「导出 JSON」下载角色卡 / 世界书两个文件。

**区块映射**（AI 适配自动完成，均逐字保留不缩略）：【开场节点】→ 节点一进「开场白」、其余节点进「替代开场白」（ST 原生"可选开局"选择功能）；角色描述 + 高频行为 → 描述；【角色备注】→ 「深度提示」（Character's Note，情景下方，带深度/角色功能，**不进描述/作者注**）；【核心规则】【特别指令】→ 「系统提示」（逐字，**不进描述**）；数值系统 → 世界书专条（`常量: 是`）。世界书条目标题（`### 条目：名称`）写入条目 comment，在 ST 编辑器中作为条目标题显示。不再生成内嵌角色书（`character_book`）。

## 输入格式（摘要）

```text
【角色卡】
名称: 林晚
标签: 武侠、江湖
描述: 多行内容用缩进续行
  第二行
开场白: …

【世界书】
### 条目：青冥剑
关键词: 青冥剑; 青冥
位置: before_char        # before_char|after_char|ANTop|ANBottom|atDepth|EMTop|EMBottom|outlet
顺序: 120
深度: 4
内容: 条目内容，`内容:` 之后直到下一个标题都是正文（冒号/# 行不会被误判）
```

说明：`开场节点`/`角色备注`/`高频行为`/`核心规则`/`特别指令` 等键也会被识别——`开场节点` 拆分进开场白/替代开场白，`角色备注` 进深度提示，`高频行为` 并入描述，`核心规则`/`特别指令` 并入系统提示（见上文「区块映射」）。

完整字段别名表见方案文档 §5（`SillyTavern-角色卡世界书生成插件方案.md`）。

## 已知限制（是刻意行为或宿主限制，不是 bug）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **反复点「应用」会多出角色卡与世界书，旧的不会自动删** | 宿主的命名策略是"只增不减"：角色卡走 `getUniqueName`（**永不覆盖同名文件**，于是 `林晚.png` → `林晚1.png`…），世界书走 `getFreeWorldName()`（**永远带 ` (N)`**）。插件不会替你删东西 | 改内容重做时，先在角色列表 / 世界书列表里删掉上一版。新建交给插件，删除永远由你决定 |
| **新角色没有头像，是 ST 的默认占位图** | ST 的 JSON 导入接口恒定写 `DEFAULT_AVATAR_PATH`（`src/endpoints/characters.js` → `importFromJson`），JSON 里没有图可给 | 建好后在角色编辑页上传头像，或把卡导出后用 ST 原生流程补图 |
| **世界书名字总是带 ` (1)`** | 同上，`getFreeWorldName()` 从 index 1 开始试，**永远不返回裸名** | 宿主行为；「命名后缀」只影响前缀部分 |
| **跨版本升级默认提示词时，会覆盖你自定义的提示词** | `promptVersion` 不一致时插件会换成新版默认提示词 | 被顶掉的旧提示词留在 `settings.ai.promptSuperseded`，可在控制台用 `SillyTavern.getContext().extensionSettings.CardLore.ai.promptSuperseded` 取回。「重置默认提示词」只会恢复默认值，**找不回**你的自定义文本 |
| **ST 首运行时改插件设置可能存不住** | 宿主 `saveSettings()` 开头是 `if (!settingsReady) return;`，而 `settingsReady` 要等首次引导走完才置真。引导没走完时**所有扩展**的设置都存不住 | 走完一次 ST 首次引导即可。宿主行为，不是插件问题 |

## 更新历史

**v1.2.4（打磨版）**
- 🐞 **修复：设置被默认值覆盖 —— 「命名后缀 / 应用前二次确认」每次刷新都被重置**（真 bug，影响所有用户）
  - 根因在初始化那一行 `Object.assign(settings, DEFAULT_SETTINGS, settings)`：**第三个参数就是 target 本身**，而它此时已经被默认值覆盖过了，那次"回填"等于空操作。于是磁盘里存的值得不到回填、一律被默认值盖掉；下一次任何 `saveSettings` 再把默认值写回磁盘，**用户改的后缀就永久丢了**。
  - 现在只补齐**缺失**字段（`undefined` 才填默认值），已存值一律不动。`ai.*` 那一组本来就是对的写法，不受影响。
  - 这条被测试假阳性掩盖了很久：老版「重载后设置恢复」探针断言的期望值**恰好等于默认值**，所以"持久化成功"和"被重置回默认"两种情况它都判通过。现在改成先写一个**不可能由默认值产生**的值、再重载，并且 DOM / 内存 / 磁盘三处一起核对。
- 🐞 **修复：角色卡导入失败时，刚建好的世界书会变成"孤儿书"**
  - 「应用」是**先存世界书 → 再导角色卡**，中间失败时原来什么都不回滚：世界书列表里留下一本没有任何角色指向的书，而且它带 ` (1)`、下次应用又是 ` (2)`，一轮一轮攒下去。
  - 现在导入失败会回滚刚建的那本世界书（回滚本身失败也会写进错误消息，让你知道要手动清一本）；同时把 ST 的失败响应（`{error: true}`，是布尔值）翻成可读错误，而不是把 `true` 直接拼进消息里。
- ⏱️ **AI 适配可中断，不会永久卡住**
  - 单次请求 **180 秒超时**；进行中可点「取消」立刻中断 —— 走 `AbortController`，一路透传到 ST 的 `ChatCompletionService.processRequest(..., signal)` 与直连接口的 `fetch`，是**真的掐断请求**，不是只停止等待。
  - **「取消」不是新按钮，而是「AI 适配」自己原地变身**（文字换成「取消」、图标从机器人换成禁止符，**配色不变**仍是琥珀色，另加一点很轻的呼吸感）。这样做是因为手机端工具栏是按**5 个按钮**硬编码 order/flex 的「3+2 两行」布局：实测塞进一个没有 order 的第 6 个按钮，行数会立刻从 2 变成 **3**、按钮宽度也从 119px 被撑到 156px。原地换文字则按钮数量恒定，PC 与手机的排列一个字都不用改。
  - 取消 / 超时不再走"失败"分支（不弹红色报错、不给"换个接口"的建议），只提示"已取消 / 已超时"；超时只判**本次请求**失败，后面的自动修正重试照常进行。
  - 「AI 适配」按钮只有在**真的可中断**时才变成取消键；写盘阶段它照旧是禁用的（点了没用的按钮比没有按钮更糟）。
  - 顺带：跨版本升级默认提示词时，把被顶掉的旧提示词留在 `settings.ai.promptSuperseded`，别让它无声消失。
